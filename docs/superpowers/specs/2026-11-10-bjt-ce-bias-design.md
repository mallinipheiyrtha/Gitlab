# BJT Common-Emitter DC Bias — Design

**วันที่:** 2026-11-10
**สถานะ:** อนุมัติแล้ว
**รายวิชา:** ENG29 2121

## บริบทและเป้าหมาย

แลปสั้นที่ต้องส่งเป็นเว็บแอป Flask จริงสำหรับคำนวณจุดทำงานกระแสตรง (DC operating point)
ของวงจรไบแอสแบบแบ่งแรงดัน (voltage-divider bias) ทรานซิสเตอร์ BJT แบบ common-emitter
ผู้ใช้กรอกค่าองค์ประกอบวงจร แล้วได้ผลลัพธ์พร้อมหน่วย มีการตรวจสอบข้อมูล มีคำเตือน
เมื่อทรานซิสเตอร์ไม่อยู่ในย่านแอกทีฟ และมีการคำนวณตรวจทานอีกวิธีหนึ่งเพื่อยืนยันผล

## แบบจำลองวิศวกรรม

### หน่วย

หน่วย SI ภายใน: แรงดันเป็นโวลต์ (V), ความต้านทานเป็นโอห์ม (Ω), กระแสเป็นแอมแปร์ (A)
หน้าเว็บแสดงกระแสเป็นมิลลิแอมแปร์ (mA) ทศนิยม 3 ตำแหน่ง และแรงดันเป็น V ทศนิยม 3 ตำแหน่ง

### วิธีหลัก — สูตรปิดแบบเทวินิน

```
VBB = VCC * R2 / (R1 + R2)
RB  = R1 * R2 / (R1 + R2)
IB  = (VBB - VBE) / (RB + (1 + beta) * RE)
IC  = beta * IB
IE  = (1 + beta) * IB
VCE = VCC - IC * RC - IE * RE
```

### การคำนวณตรวจทานอิสระ — ระเบียบวิธีเชิงตัวเลข

แก้สมการ KCL ที่โหนดเบสด้วยวิธีแบ่งครึ่งช่วง (bisection) 200 รอบ โดยไม่ผ่านการลดรูปเทวินิน

```
f(VB) = (VCC - VB) / R1 - VB / R2 - max(0, VB - VBE) / ((1 + beta) * RE)
```

`f` เป็นฟังก์ชันลดลงอย่างเดียวบนช่วง `[0, VCC]` จึงมีรากเดียว
เมื่อได้ `VB` แล้วคำนวณ `IB`, `IC`, `IE`, `VCE` ด้วยสูตรเดียวกับแบบจำลองอุปกรณ์

ผลทั้งสองวิธีต้องตรงกันภายใน relative tolerance `1e-6` (มี absolute floor `1e-9`)
หน้าเว็บแสดงผลทั้งสองวิธี ค่าแตกต่าง และสถานะ "ตรงกัน/ไม่ตรงกัน"

### การแบ่งย่านการทำงาน

- `IB <= 0` → `cutoff` (IC = IE = 0, VCE = VCC)
- `VCE <= 0.2 V` → `saturation` (รายงานค่าจากสมการแอกทีฟพร้อมคำเตือนว่าใช้ไม่ได้จริง)
- นอกนั้น → `active`

ค่าคงที่ `VCE_SAT_V = 0.2`

ข้อความคำเตือน (ต้องตรงตามนี้):

- cutoff: `ทรานซิสเตอร์อยู่ในย่านคัตออฟ (IB = 0) — ไม่มีกระแสสะสม`
- saturation: `ทรานซิสเตอร์อยู่ในย่านแซทเทอเรชัน (VCE ≤ 0.2 V) — ค่าที่ได้จากสมการแอกทีฟใช้ไม่ได้จริง`
- active: ไม่มีคำเตือน (`None`)

### การตรวจสอบข้อมูล

ทุกช่องต้องมีค่า เป็นตัวเลข และเป็นจำนวนจำกัด (finite) จากนั้น:

| เงื่อนไข | ข้อความ |
|---|---|
| ช่องว่าง | `กรุณากรอกค่านี้` |
| แปลงเป็นตัวเลขไม่ได้ | `ต้องเป็นตัวเลข` |
| `inf` / `nan` | `ต้องเป็นตัวเลขจำกัด` |
| `VCC <= 0` | `ต้องมากกว่า 0` |
| `R1, R2, RC, RE <= 0` | `ต้องมากกว่า 0` |
| `beta <= 0` | `ต้องมากกว่า 0` |
| `VBE <= 0` หรือ `VBE >= VCC` | `ต้องอยู่ระหว่าง 0 ถึง VCC` |

เก็บข้อผิดพลาดได้หลายช่องพร้อมกัน ถ้ามีข้อผิดพลาดจะไม่คำนวณเลย

## เว็บแอป

- `GET /` แสดงฟอร์มพร้อมค่าตั้งต้น: `12, 47000, 10000, 4700, 1000, 100, 0.7`
  → IC ≈ 1.286 mA, VCE ≈ 4.655 V, แอกทีฟ
- `POST /calculate` ตรวจสอบและคำนวณ แล้ว render หน้าเดิม (HTTP 200 ทั้งกรณีสำเร็จและผิดพลาด)
  คงค่าที่ผู้ใช้กรอกไว้
- ส่วนผลลัพธ์มี `id="results"` ประกอบด้วย ป้ายย่านการทำงาน ตารางผล กล่องคำเตือน
  และแผงตรวจทานที่แสดง "ตรงกัน" หรือ "ไม่ตรงกัน"
- ใช้ Jinja ฝั่งเซิร์ฟเวอร์, CSS ไฟล์เดียว, ไม่มี JavaScript
- ข้อความ UI ภาษาไทย ใช้ศัพท์วิศวกรรมอังกฤษกำกับ

## เทสต์

- กรณีตัวอย่างจากตำรา (แอกทีฟ)
- กรณีคัตออฟ และกรณีแซทเทอเรชัน
- กฎตรวจสอบข้อมูลทุกข้อ รวมถึง `inf`, `nan`, ช่องว่าง และจุลภาคทศนิยม
- ผลตรงกันของการคำนวณสองวิธีบนชุดค่าหลายชุด
- ตรวจจับกรณีผลไม่ตรงกัน
- route `GET /` และ `POST /calculate` ทั้งสำเร็จและผิดพลาด
- ยืนยันว่า `bjt.py` ไม่ import Flask (ตรวจใน subprocess)

## เดโมและ git

1. สร้าง `.venv` และติดตั้ง `requirements.txt`
2. รันเทสต์ทั้งหมดให้ผ่าน
3. เปิด `py -m flask --app bjt_bias.app run` ที่ `http://127.0.0.1:5000`
4. ตรวจว่า `GET /` และ `POST /calculate` ทำงาน
5. commit บน branch `feature/bjt-bias`
6. merge เข้า `main` และ push ขึ้น `origin/main`

## การตัดสินใจที่ล็อกไว้

- แอปใหม่อยู่ในโฟลเดอร์ `bjt_bias/` ไม่แตะแลปเก่า
- UI ภาษาไทย, อินพุตความต้านทานเป็นโอห์ม
- `VCE_SAT_V = 0.2` คงที่

- ไม่มีกำลังไฟฟ้าในเอาต์พุต

## ความเสี่ยงที่รู้ตัว

- ผู้ใช้อาจกรอกความต้านทานเป็น kΩ (เช่น 47 แทน 47000) แล้วได้ผลผิดโดยไม่มีการเตือน
  → บรรเทาด้วยป้ายหน่วย Ω ในฟอร์มและ README ที่ชัดเจน
- ในย่านแซทเทอเรชัน `VCE` ที่คำนวณได้อาจติดลบ ซึ่งไม่มีความหมายทางกายภาพ
  → แสดงค่าตามจริงพร้อมคำเตือน ไม่ตัดทิ้ง
- ตัวเลขทศนิยมแบบจุลภาค (`12,5`) จะถูกปฏิเสธเป็น "ต้องเป็นตัวเลข"
  → ยอมรับได้ ระบุใน README ว่าให้ใช้จุดทศนิยม
